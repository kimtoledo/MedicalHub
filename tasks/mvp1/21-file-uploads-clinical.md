# Clinical File Uploads (X-rays & Photos)

> **Status:** 🔲 Queued — MVP 1 (Increment 5)
> **Proposal alignment:** Executive Summary §3-F — File Upload Module
> **Project task:** #24

---

## What & Why

Dentists attach radiographs and intraoral photos to almost every encounter. The executive summary includes basic file upload in the product MVP. This task promotes clinical file uploads from MVP 2 into MVP 1, using Replit Object Storage for private file hosting.

---

## Done looks like

- From within an encounter, dentist or staff can upload: radiographs, intraoral/extraoral photos, consent forms, lab results, referral letters.
- Each file is tagged: patient, encounter, file type, optional tooth reference, upload date, uploaded by.
- Files are stored in **private** Replit Object Storage — never publicly accessible via a direct URL.
- Access is via a **short-lived signed URL** (~15 min) generated by the API per request.
- A basic inline viewer shows images (JPEG/PNG/WebP); PDFs open in a new browser tab.
- Upload validation: file type allowlist (JPEG, PNG, WebP, PDF, HEIC), max 20 MB per file.
- Files are tenant-scoped; the API rejects any cross-clinic access attempt.
- Encounter "Files" tab lists all uploaded files with thumbnails and metadata.
- Patient profile has a "Files" tab aggregating files across all encounters.
- Upload and signed-URL access events are written to `audit_events`.

---

## Out of scope

- Patient-accessible file downloads (MVP 3 patient portal — `tasks/mvp3/01-patient-portal.md`).
- Video recordings.
- AI radiograph interpretation (MVP 3 — `tasks/mvp3/12-ai-imaging.md`).
- Malware scanning (future hardening).

---

## Steps

1. **Storage setup** — Configure Replit Object Storage bucket; implement signed URL generation helper in the API layer.
2. **Schema** — Add `clinical_files` table (patient_id, encounter_id, file_type, storage_key, original_filename, mime_type, size_bytes, tooth_ref, uploaded_by, timestamps); generate and apply migration.
3. **Upload endpoint** — Multipart upload API route: validate type/size, write to Object Storage, insert metadata row.
4. **Signed URL endpoint** — Separate API route that generates and returns a short-lived access URL given a `clinical_file_id`.
5. **Encounter file tab** — File list component on the encounter detail: thumbnails, metadata, inline viewer for images, link-out for PDFs.
6. **Patient files tab** — Aggregated file list on the patient profile.
7. **Audit** — Write audit entries for uploads and signed URL requests.
